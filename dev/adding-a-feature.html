Adding a feature

Adding a feature: the checklist#

Every user-facing feature touches the same five places. Skipping one either fails CI or leaves the docs/palette out of sync (the smoke suite catches that too).

  1. Logic in Core. Write the testable rules in Playcraft.Core with XML doc comments (missing docs on public APIs fail the build) and unit tests in tests/Playcraft.Core.Tests (the 80% coverage gate applies).

  2. Adapter in the plugin. Add the [CommandMethod("PBXXX")] shim in src/Playcraft.Plugin, collecting drawing data and delegating to Core. Stick to ApplicationServices.Core APIs so the command still works under accoreconsole.

  3. Declare it in data/features.json. This is the single source of truth for the palette AND the User Guide tab:

    {
  "command": "PBXXX",
  "userDescription": "What a designer sees in the palette and docs.",
  "category": "Layout",
  "screenshotPath": "images/pbxxx.png",
  "addedInVersion": "0.2.0"
}

    Playcraft.Core.Tests validates the file’s schema; the smoke suite verifies every declared command actually exists in the built plugin.

  4. Screenshot (optional but encouraged). Drop it at docs/site/static/images/pbxxx.png. Until it exists, set screenshotPath to null and the docs will skip the image gracefully.

  5. Rebuild the docs with docs/build-docs.ps1 and eyeball the User Guide tab. CI regenerates the site on every push, so drift can’t survive a PR.
