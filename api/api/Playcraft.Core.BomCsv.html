Class BomCsv

Composes the priced, sectioned, per-level BOM as CSV text — the office file for sales, purchasing and the factory (execution plan Item 3). Pure text composition so the layout is unit-testable; the Cad layer owns the file write and its encoding (UTF-8 with BOM, so Excel detects it).

Remarks

Layout decisions, so they are deliberate rather than incidental:

  • The column header is ROW 1 and every data row fills the Section and Level columns, so the sheet pivots and filters as a flat table; subtotal rows have an empty Part cell, which is the filter that excludes them.
  • Subtotal rows carry quantity only. Money appears on data rows and on the one Design total row, whose numbers are PricedBomResult's own totals — the same object PBPRICE prints, so the two can never drift. A partial money subtotal over a section with unpriced lines would be a lie.
  • Everything is invariant-culture: decimal POINTS, comma separators, CRLF row ends (RFC 4180). A price of 1234,56 in a comma-separated file is how a quote silently loses its cents on a German-locale workstation.
  • The honesty notes ride at the bottom. The command line says when a total is incomplete or a count leans on a guess; a file that dropped those would launder the uncertainty out of the same numbers.
This is NOT the native DATAEXTRACTION table (ADR §5.1) — this file carries computed data (resolved prices, structure grouping, levels) the drawing does not display; the table carries only what the drawing shows.

The flat priced result — the totals authority, allowance row included. Built by the same calls PBPRICE makes, which is what makes "totals match PBPRICE" true by construction rather than by coincidence.
