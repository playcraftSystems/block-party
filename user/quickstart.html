Playcraft Suite quick start#

Playground design tools for AutoCAD 2027.

The six you will use every day:

Command For
PBCATALOG Find a part and place it.
PBSTAMP Keep placing, snapped to what is already there.
PBGEN Puts the posts right and names the structures; posts already follow every edit.
PBFILL Barrier fillers in the gaps between them.
PBPANEL Live count and price, open while you work.
PBBOM The parts list, structure by structure.

PBHELLO prints the build you have loaded. Paste that line into anything you report.

Install#

Download: https://github.com/playcraftSystems/PlaycraftSuite/releases/latest/download/Playcraft.bundle.zip

The repo is private, so open that link in a browser signed in to a GitHub account that has access. An anonymous download returns 404.

  1. Download Playcraft.bundle.zip.
  2. Extract the whole zip. The installer will not run from inside it.
  3. Run install.cmd. It installs per user and needs no admin rights.
  4. Restart AutoCAD 2027.

You need Windows x64, AutoCAD 2027, and access to the component library folder (local or network). A pricing token is optional and affects only live pricing and PBSYNC.

Update: run the new zip’s install.cmd. Uninstall: delete %APPDATA%\Autodesk\ApplicationPlugins\Playcraft.bundle. Developers: dotnet build PlaycraftSuite.slnx -c Release, then NETLOAD the DLL. See the README.

First run#

If no library is configured, the setup window opens by itself. PBSETUP reopens it any time.

  1. Browse to the folder whose children are the family folders (Access Components, Decks, and so on). The window reports what it found, such as 233 families, 6516 components. A wrong folder reads back 0 families before anything is saved.
  2. Paste a pricing token if you have one and press Test connection. Blank is fine.

Without a library everything still runs, but parts place as labeled placeholder blocks instead of real geometry.

Commands#

* marks commands that need the component library.

Setup#

Command What it does
PBSETUP Setup window: library folder and pricing token, both checked on the spot.
PBVAULT Set the library path from the command line. Reports what it finds there.

Place parts#

Command What it does
PBCATALOG * Catalog panel. Search, browse by family, filter by age group or price, sort any column. Double-click a part to place it. Best matches come first; part numbers ignore dashes, "quote a phrase" keeps it together, and -word leaves one out.
PBFIT * Click a placed part. The catalog then lists only parts that fit it.
PBSTAMP * Placement loop. A ghost follows the cursor and snaps to compatible connection points; click inside a placed deck to stack the next storey on it. The words at the cursor say what it holds, or why it can’t attach and where it could. While placing, type Next to attach by another side, Angle to type an angle for parts that don’t snap, Rotate or Counter to turn them 15° either way, Turn for half a turn, and Free to switch the magnet off and on. Click to place, Enter to finish.
PBROT15, PBROTBACK15 Turn the selected parts 15° either way: PBROT15 counter-clockwise, PBROTBACK15 clockwise. The ⟲ ⟳ buttons on the catalog panel do the same. A selection with a deck in it turns as one structure about its first deck. One UNDO takes a turn back.
PBATTACH * Click near a deck edge to snap the 24 inch Poly Wave Slide onto the nearest free point. Place other slides from the catalog.
PBMATES Show every connection point in the drawing — green free, grey taken. Run again to hide. Drawn over the drawing, never added to it.

Structure#

Command What it does
PBGEN Put the posts right: every part’s posts, one post where parts share one, each sized for the tallest part on it. Posts already follow every edit, plain MOVE, COPY and grips included; run this to check, or after an UNDO. No prompts.
PBFILL * Place the barrier fillers that close gaps where decks of different heights share posts. Re-run to update. No prompts.
PBHEIGHT Change a placed deck’s height. Click a deck, or press Enter for every deck. Heights step by 6 inches and are checked against the deck’s age ratings. The deck’s posts and fillers follow inside the same edit.
PBLEVEL List the drawing’s storeys — which level each component stands on, exactly as an export will number them. Imported designs keep the file’s own storey numbers; native parts derive theirs. Name a level to select everything on it, or answer Layers to file each storey onto its own PB_LVL layer — freeze a tier to hide it and build on the one above (counts and exports still see it). Placing, importing, and height edits keep the layers fresh; delete the PB_LVL layers to stop.
PBMIGRATEZ Lift an older flat drawing to real heights. Parts whose height label proves where they belong move there; anything unproven stays flat and is named. Safe to re-run.

View in 3D#

Command What it does
PB3D * Live 3D panel of every placed part, updating as you edit the 2D plan. Drag to orbit, right-drag to pan, wheel to zoom. Click a part to select it in the drawing. Parts with no 3D model show as orange boxes.

Count and price#

Command What it does
PBBOM Parts list tallied by part number, split into sections by structure. Fully offline. Also breaks parts into their sub-parts when the parts database is set up.
PBPRICE Parts list with MSRP and REP prices. Live prices with a token, the built-in price list otherwise.
PBEXPORTBOM Save the priced parts list as a CSV that opens in Excel — sections by structure, rows split by level, totals matching PBPRICE.
PBPANEL Live priced parts panel, including posts, collars, caps, and hardware. Updates after every edit.
PBSYNC Refresh catalog data cached in the drawing. The only command that requires the pricing token.

Design files (.kcd)#

Command What it does
PBKCDINFO Show component, post, and filler counts per tab. Does not touch the drawing.
PBIMPORTKCD * Import a .kcd tab at exact positions and rotations. Re-importing the same tab replaces instead of duplicating.
PBEXPORTKCD * Write the drawing out as a .kcd. Patch the file it came from, or author a new one. A .json copy is written alongside.
PBDEPS * Audit a .kcd for missing required attachments and broken links, then list the drawing’s own pairings (a sit-down wall and its slide) read from where the parts stand. Report only.

Diagnostics#

Command What it does
PBAUDIT Check the drawing against the design team’s rules — barriers on decks 108" and up, stepping distances, Geo-Wave and traverse heights, ground panels, limb-climber models, mirrored or scaled parts, parts that almost touch — plus the storey check when a design file is open. Every finding names the part and cites the wiki card it came from. Report only; it never changes anything.
PBHELLO Print one line naming the build that is loaded. Paste it into anything you report.
PBNUDGE Test-script helper. Use the normal MOVE command instead.

Your first layout#

  1. PBCATALOG, double-click Square Deck, accept height 48, click 0,0, click 48,0, press Enter. Two decks, snapped flush, and their posts with them: every part brings its own posts as you place it, and the two posts on the shared edge are one post each, sized for the tallest part standing on it.
  2. PBPANEL. Decks and posts counted and priced, live from here on.

Posts follow every Playcraft edit by themselves: placing, attaching, nudging, changing a height, importing and erasing. One UNDO takes back a part and its posts together.

Placing by hand#

You can always finish a layout with plain AutoCAD. A part placed by hand counts exactly as if the catalog had snapped it: same posts, same fillers, same quote.

  • Land it exactly with Node snap. Every part’s connection points, posts included, are Node snap targets. MOVE the part by its connection point and drop it on its neighbour’s.
  • A part from the catalog: place it anywhere clear from PBCATALOG, then MOVE it into place with Node snap. A block inserted with AutoCAD’s INSERT counts after its next edit.
  • The command line says what followed. After a MOVE, COPY, ROTATE, STRETCH or grip edit of a part: Posts follow the MOVE: 2 added, 0 re-sized, 4 removed., Fillers follow the MOVE: 1 placed, ... when a height step changed, and 1 dependent(s) paired with their owner by position. when a sit-down wall now stands on its slide.
  • Close is not attached. A part left a little short gets a line like S-1101-R5 at (0, 0) is 2" from S-1101-R5 at (43, 0): not attached. Posts and the quote will treat them as separate. Use Node snap to land it exactly. Nothing is moved for you: MOVE it again with Node snap. PBAUDIT lists every such pair in the drawing.
  • One UNDO takes back a move and the posts, fillers and pairings that followed it.

Turning a part#

  • While placing, type the angle. In PBSTAMP, type Angle and then the degrees (45, or -30), or Rotate / Counter for 15° either way and Turn for 180°. The angle stays for the rest of the run, so a row of loose decks or benches all come out the same way. A part that snaps takes its angle from what it attaches to.
  • Change the side it attaches by. A part attaches by its side nearest the cursor. When the magnet holds a point a bridge or a stair could take either way, type Next and the ghost flips to the other end; the words say which side and “2 of 2”.
  • Swing a panel on a post. Over a post, a panel or other post-mounted part holds that post and swings round it with the cursor. It settles along the deck’s edge or toward another post; aim it and click, and its far post comes with it.
  • Line a part up with a fence or path afterwards. Use AutoCAD’s own ROTATE with the Reference option: pick two points along the part’s edge, then type Points and pick two along the fence. Posts and fillers follow as for any other ROTATE.

Start from a design you already have#

Most jobs do not start on an empty sheet.

  • A .kcd design file. PBKCDINFO first to see what is in each tab without touching the drawing, then PBIMPORTKCD to bring one in at its exact positions, rotations and heights. Re-importing the same tab replaces rather than duplicates, so pulling a corrected file again is safe.
  • An older Playcraft drawing drawn flat. PBMIGRATEZ. Parts whose height label proves where they belong are lifted; anything unproven stays put and is named. Safe to re-run.

PBEXPORTKCD writes it back out, patching the file it came from or authoring a new one. PBDEPS audits a .kcd for missing attachments and broken links.

An imported design arrives fully built, so most connection points are already taken. A part refusing to snap is usually that, not a bug — run PBMATES and look for grey.

Group each structure#

A quote has to read structure by structure. A customer will not accept a price list where every part is in one pile with no idea which structure it belongs to.

So tell the drawing what a structure is. Build one, run GROUP, name it, and select it.

Command: GROUP
Select objects or [Name/Description]: N
Enter a group name or [?]: ToddlerArea
Select objects or [Name/Description]: (window the structure)
Select objects or [Name/Description]: (press Enter to finish)

The N on the second line is a menu choice, not the name. Typing the name at that prompt gives you *Invalid selection*, because AutoCAD is still asking what to select. N switches it over to asking for a name, then puts you back to selecting.

You do have to type N at some point. Skip it and AutoCAD makes an unnamed group, and an unnamed group cannot be a heading on a quote. Order does not matter: you can select the parts first and type N afterwards.

If the name gives you any trouble, select the parts first, then run CLASSICGROUP instead. That opens a dialog with a real text box. Type the name under Group Name, click New, window the parts, press Enter, click OK. Slower, but there is nothing to mistype. It is also how you rename a group later, and the only reliable way to put a space in a name.

Use the name the customer should see. ToddlerArea, 5-12 Composite, Main Structure. That exact text becomes the heading on the parts list and the quote, so it is worth typing properly the first time.

Do one structure, then the next. One group per structure. Do not nest them.

A few things happen for you after that:

  • Each new post goes in the group of the first part standing on it.
  • PBFILL puts each filler in the group of the deck it hangs off.
  • PBATTACH and PBSTAMP put a part in the group of whatever it snapped onto.

So you can group a structure early and keep working on it. You do not have to regroup it every time you add something.

Benches, trash cans, and other site items can be left loose. They sort themselves onto the quote under Site Amenities based on what they are. Group them only if you want them under a heading of your own.

Swings are usually all one group. If you use the same swing set on lots of jobs, save it as its own drawing and bring it in with XREF instead. An external reference comes through as its own section, named after the drawing.

Do not turn a structure into a block. Grouping is safe and blocking is not. A block hides every part inside it, so they vanish from the parts list and the quote with no warning. Worse, if you block some of a structure and not the rest, posts inside the block cannot be changed (they are named, never rewritten) and the next PBFILL cannot see the fillers in it. Use GROUP.

Run PBBOM when you are done. It prints your structures by name, then anything brought in by reference, then loose site items, then shared hardware. If it reports parts as Unassigned, those are decks, posts, or fillers that are not in any group yet.

If something looks wrong#

Symptom Fix
Parts place as placeholder blocks The library is not reachable. Run PBSETUP and read what it reports.
A part will not snap where it should Run PBMATES. Grey means that point is already taken, which is the usual answer. Green and still refusing is a bug — report it.
A search finds nothing you recognise Check the family and age filters, or press Clear all. A leading minus excludes a word, so -R5-04ft pasted from a quote will fight you — drop the first dash.
A part vanished from the quote It was exploded, which stops it being a component. UNDO brings it back.
PBBOM says parts are Unassigned Those decks, posts, or fillers are in no group. Select the structure, run GROUP, and name it.
Two parts look joined but quote extra posts They are a little apart. The line after the edit, or PBAUDIT, names the gap. MOVE one with Node snap.
One structure prints as two sections Its decks are split across two groups. PBGEN and PBBOM both report this. Put them in one group.
A whole structure is missing from the parts list It was made into a block. Explode it, then GROUP it instead.
Setup says 0 families The path is one level off. Pick the folder whose children are the family folders.
PB commands missing after install Wrong AutoCAD year (2027 only), or the zip was not fully extracted before running install.cmd.
No live prices No token, or it was revoked. PBSETUP, paste the token, Test connection. Offline prices keep working.

More detail: INSTALL.md and the User Guide.

Tell us what you find#

Send it however you already send things. What matters is the shape:

Build:      (the line PBHELLO prints)
Doing:      what you did, in order
Expected:   what you thought would happen
Happened:   what actually did

The Expected line is the one people leave out and the one we need most — it is the only way to tell a bug from a disagreement about how it should work.

Worth noticing while you work: where it fought you, where it was wrong, and what you expected to be there and wasn’t. A screenshot of the command line beats a description of it, and the drawing itself beats both.
