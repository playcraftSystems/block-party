User Guide

Every feature, and why it is there#

28 commands. Type one at the AutoCAD command line.

Each entry below says why the feature was built, then how to use it. The sections run in the order a designer meets them: set the library up, place parts, build the structure, look at it, count it, send it out, check it.

New here? Read the Quick Start first. It installs the plugin and walks one small layout end to end.

Setup

PBSETUP

A new machine needs two answers: where the component library sits, and whether live pricing is allowed. Typed into a config file, both were wrong silently.

It opens by itself the first time, when the library folder is missing. Browse to the folder whose children are the family folders. The window reports what it found before anything is saved, so a wrong path reads as 0 families on the spot. Paste a pricing token if you have one and press Test connection. Blank is fine. Run PBSETUP again whenever either answer changes.

Added in version 0.8.0

PBVAULT

The same setting from the command line, for scripts and for a quick check of what the plugin can actually see.

Type the path. It answers with families, components, and which data files it found. The choice is saved per user and announced at every load. Parts already placed keep their look; new placements read the new library. An environment-variable override wins over the saved path, and the command says when it does.

Added in version 0.7.0

Place parts

PBCATALOG

The library runs to thousands of components across hundreds of families. Scrolling a tree to find one is slow, and the file's own order is never the order you want.

Search by name or by part number. Punctuation is ignored, so S-1101-R5, s1101r5 and 1101 all find the same deck. Quote a phrase to keep it together. Put a minus in front of a word to leave it out. Filter by age group or a price cap. Every column sorts, MSRP included; a part with no price shows a dash and sorts to the bottom whichever way the column points. Hover a row for the component's photo. Double-click to place it. One mistyped letter still finds the part, and the panel says it did. Families the library inserts on its own stay hidden.

Added in version 0.4.0

PBFIT

The first question at a deck edge is what fits here. The library knows. You could not ask it.

Click a placed part. The catalog reopens holding only the parts that mate with it, match its rail system, and are rated for its height. Click a 48 inch deck and you get the climbers, slides and panels that work at 48 inches.

Added in version 0.4.0

PBSTAMP

Part after part, you need to know before the click whether it will attach. Without that you place, look, undo.

A ghost follows the cursor and snaps to the library's connection points. Points within four feet are drawn: green where the part can land, grey where something already sits. The words ride the cursor at a size you can read at any zoom and name the distance to the nearest free point, or say the points in reach are taken, or that this deck doesn't take this part, what it does hang on, and how far away the nearest point that would take it is. When the magnet holds a point it names what it holds and the side the part attaches by, so at an edge two storeys share you can see which deck the part will serve. A part attaches by its side nearest the cursor; where a bridge or a stair could attach either way, type Next and the ghost flips to the other end. Over a post, a post-mounted part holds the post and swings round it with the cursor, settling along the deck edge or toward another post. A part about to land unattached turns red before you click. Parts that don't snap take an angle: type Angle and the degrees, Rotate or Counter for 15 degrees either way, Turn for half a turn; the angle stays for the rest of the run. Type Free to drop the magnet. Click as often as you like; Enter ends it. Decks ask their height first and carry the label. Click inside a placed deck to stack the next storey on it; a deck at the same height is refused and the deck already holding that level is named. Parts that cannot stand alone arrive with what they need, matched to the rail system they landed on.

Added in version 0.6.0

PBROT15

Turning a part a little should take one click, not a trip through ROTATE.

Select parts and run it, or click the counter-clockwise turn button on the catalog palette. Each part turns 15 degrees counter-clockwise about its own insertion point; a selection that holds a deck turns as one structure about its first deck. It is AutoCAD's own ROTATE underneath, so one U takes it back and posts and fillers follow as they do for any ROTATE. For any other angle, or to line a part up with a fence, use ROTATE itself.

Added in version 0.16.0

PBROTBACK15

The same one-click turn, the other way.

As PBROT15, but 15 degrees clockwise. The clockwise turn button on the catalog palette runs it, and one U takes it back.

Added in version 0.16.0

PBATTACH

One slide gets placed more than any other. It should not cost a trip through the catalog.

Click near a deck edge. The 24 inch wave slide lands on the nearest free connection point within 8 inches. Incompatible pairs are refused and taken points are skipped. Every other slide places from the catalog.

Added in version 0.1.0

PBMATES

A part that will not snap reads as a bug. Usually the point is simply taken, and nothing on screen said so.

Run it. Every connection point in the drawing is marked: green free, grey taken. Run it again to hide them. The marks are drawn over the drawing, never added to it, so there is nothing to erase, nothing that plots, and no effect on the parts list. They are a snapshot of the moment you asked. After moving or placing something, run the command twice to refresh.

Added in version 0.12.0

Structure

PBGEN

Every part stands on posts, and where parts meet they share one. Posts already follow every Playcraft edit; plain AutoCAD MOVE, COPY and grips are the edits they cannot see, and the quote pays for every post left wrong.

Run it after moving or copying parts with plain AutoCAD. No prompts. Every part brings the posts its library record names, not only decks. Posts closer than an inch are one shared post, sized for the tallest part standing on it by the legacy design tool's own rule, and carry the real whole-foot catalog part number. Posts already in place are kept, wrong lengths are re-sized, missing ones added and posts nothing stands on removed. A designer's own cut post is never changed; a disagreement is named instead.

Added in version 0.1.0

PBFILL

Where decks of different heights share posts there is a gap, and the gap needs a barrier. Choosing the right filler for every edge length and every step is bookkeeping, not design.

Run it. No prompts. Each height step gets the filler its edge length calls for. Run it again after decks move, change height, or go away: fillers are kept, swapped, or removed to match. One you swapped for an equivalent style is kept. Imported decks that arrive without post data keep their fillers, and the report says how many it could not verify.

Added in version 0.5.0

PBHEIGHT

You build a second storey by raising decks. Until this, changing a height meant erasing the deck and placing it again.

Click a deck, or press Enter for every deck, then give the new height. Heights step by 6 inches, run from 6 to 156, and must sit inside that deck's own age ratings. A refused height says why and leaves the deck where it was. The tag and the visible label change together. The deck's posts are re-sized inside the same edit, so one UNDO takes back both, and step fillers swap because PBFILL runs itself afterwards. Attached parts keep their own height, so re-place them if the new height changes what fits. The edit survives export back to the design file.

Added in version 0.11.0

PBLEVEL

A tower is storeys, and a designer wants to turn one off and build on the one above it.

Run it for the list: every component and the level it stands on, numbered exactly as an export writes it. Imported designs keep the file's own storey numbers; parts placed here derive theirs from what stands on what, so a tall shade post is still ground-storey furniture. Then answer the prompt. Name a level to select everything on it and move, measure or inspect the storey as one thing. Answer Layers to file each storey onto its own layer, PB_LVL0, PB_LVL1, and so on. Freeze a layer to hide that tier and build on the one above: posts, fillers, counts and exports still see everything on it. Placing, importing and height edits keep the layers fresh and report what changed tier. Delete the layers to stop. It never edits a component or the design file.

Added in version 0.13.0

PBMIGRATEZ

Drawings made before heights were real sit flat on the ground. The 3D view and the storey list need them lifted.

Run it once. Every part whose height label proves where it belongs moves there. Carried attachments follow their owner. Posts stay at grade. Anything without that evidence stays where it stands and is named in the report. It moves parts and never erases them. Run it again on a lifted drawing and it finds nothing to do.

Added in version 0.13.0

3D view

PB3D

A plan view hides the thing you are selling. Designers asked to see the structure while they drew it.

Toggle the palette. Every placed part renders from the library's own 3D model: decks at their design height, posts stretched to their part height, slides and climbers at the deck they serve. The picture follows every 2D edit. Drag to orbit, right-drag or middle-drag to pan, wheel to zoom. Click a part in 3D to select it in the drawing. Parts with no 3D model show as orange boxes and are listed by part number, so nothing goes missing quietly.

Added in version 0.10.0

Count and price

PBBOM

The parts list is the job. A customer will not accept one pile of parts with no idea which structure they belong to, so it reads structure by structure.

Run it. Every placed component tallied by part number, with quantities and descriptions, in sections by structure. Fully offline: the tallies come from data cached in the drawing. With the parts database configured it also breaks each part into the smaller parts that make it up, as many levels deep as the data goes. A count it cannot settle says so in a note instead of guessing, and a sub-item row it cannot read is counted conservatively and named. Parts printed as Unassigned are in no group yet.

Added in version 0.1.0

PBPRICE

The price is what gets asked for first. It should come off the drawing, not off a spreadsheet typed up afterwards.

Run it. Unit MSRP, then extended MSRP and REP totals for the layout. With live pricing configured, MSRP is fetched fresh every run in the background, so AutoCAD stays responsive. Without it the built-in price list keeps the numbers coming offline. The table names its price source and flags any part with no price on file rather than hiding it from the total.

Added in version 0.1.0

PBEXPORTBOM

Sales, purchasing and the factory need a file. They do not have AutoCAD open.

Run it and choose where it lands; it suggests the drawing's name with -bom. The CSV opens cleanly in Excel with the same structure sections, the same per-level rows, and the same MSRP and REP totals as PBPRICE, because both read one tally and one set of prices. The notes print into the footer, so the file is as honest as the screen was.

Added in version 0.13.0

PBPANEL

Price matters while you are still deciding. Re-running a count after every edit is a tax on the decision.

Toggle the palette and leave it open while you work. Parts, support posts, collars, caps and connection hardware, with MSRP and REP totals, recomputed after every edit. Place, move or erase something and the numbers follow. An OFFLINE badge appears when live prices are out of reach; hover it for the price source. Refresh Prices re-checks on demand.

Added in version 0.2.0

PBSYNC

Names, descriptions and weights live in the web catalog. The drawing carries a copy so it works offline, and a copy goes stale.

Run it. The cached catalog data refreshes in one batched lookup, in the background, so AutoCAD stays responsive. It is the only command that needs the pricing token. Between syncs the drawing keeps working offline.

Added in version 0.1.0

Design files (.kcd)

PBKCDINFO

Most jobs do not start on an empty sheet. Know what is in a design file before any of it lands in your drawing.

Pick a .kcd file. It prints per-tab counts: components, distinct support posts, attachment points, fillers. It does not touch the drawing.

Added in version 0.3.0

PBIMPORTKCD

The designs already exist. Redrawing one by hand is the job done twice.

Pick a file, then a design tab. Every component lands at its exact position, rotation and height, with real library geometry where there is any, engineering drawings next, labeled placeholders last. Without a library configured, most parts land as placeholders. Re-import the same tab and it replaces the earlier import instead of duplicating it. The design's posts arrive as posts, each knowing the parts standing on it, and nothing the file holds is re-sized or removed on load; posts whose saved owner list disagrees with where the parts stand are named. The summary checks the file's declared post count against the geometry that arrived. It also checks the file's hand-typed storey numbers against the geometry, names what disagrees, and changes nothing.

Added in version 0.3.0

PBEXPORTKCD

Work done in AutoCAD has to come back out, because the design file is what the rest of the company reads.

Patch the design the drawing came from, or author a new file when the layout was built here from scratch. It always writes to a destination you choose, a fresh -export copy by default, so the original is never touched unless you point at it. Moves land. Deletions land, as long as part of that import is still in the drawing. Parts added in AutoCAD are written in as new, with support posts shared correctly across neighbouring decks. Posts are written as posts, with the parts standing on each one, so the legacy tool reopens them with the same lengths. A slide and the wall it carries are exported with their pairing recorded. When patching, everything else in the original file passes through untouched. A .json copy is written alongside for web and API use.

Added in version 0.3.0

PBDEPS

A slide without its sit-down wall fails review, and the quote is short a part.

Pick a .kcd file. It reports slides missing a required sit-down, attachments whose parent component is gone, links pointing at components the file no longer holds, and pairs linked in one direction only. Where the design was imported here, it gives drawing positions for what it can locate. It needs the library's catalog data and refuses to run without it, rather than print a clean report it cannot stand behind. Report only.

Added in version 0.6.0

Diagnostics

PBAUDIT

Leads check designs against the team's own rulebook by hand. A good share of those rules are arithmetic on data the drawing already holds.

Run it. It flags elevated decks at 108 inches and up with edges that hold nothing, Geo-Wave links whose tallest end is over the limit, traverse take-offs above the maximum landing height, standard ground panels under a deck too tall for them, Conifer and Oak limb climbers that are the wrong model for their deck or too far from it, and any component that has been mirrored or scaled, which the quote would price as the standard part. With a design file open it adds the storey check and reads the safety limits at that design's own age range. Every finding names the part, gives a position to drive to, and cites the wiki card the rule came from, so a rule you disagree with is a conversation about the card. What it could not settle is printed as plainly as what it found. Report only: it never moves, refuses or repairs anything.

Added in version 0.14.0

PBHELLO

Half of a bug report is which build was loaded.

Run it. It prints one line naming the build. Paste that line into anything you report.

Added in version 0.1.0

PBNUDGE

The drawing tests need a move they can drive without a mouse.

Not for design work. Use AutoCAD's own MOVE. This one exists so an automated test can displace a part by a known amount.

Added in version 0.1.0

PBLIBCHECK

The part drawings are the library now. Someone has to be able to show that every drawing reads and that its connection points line up with the facts kept beside it.

Not for design work. Maintainers run it through build\library-check.ps1, which opens every part drawing read-only and writes a report into the repository. It refuses to write anywhere inside the component library.

Added in version 0.15.0
